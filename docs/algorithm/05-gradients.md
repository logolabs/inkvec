# Stage 05 — Gradients

> Turns a stack of flat, palette-quantised bands back into the smooth gradient fill that produced them, and fits every region's fill — flat, linear or radial — by minimum description length against the image.

**Source:** `crates/inkvec-trace/src/gradient.rs` (2771 lines — the largest module in the tracer)
**Entry points:** `merge_gradient_bands_with_ink()` (`gradient.rs:2138`), `carve_residual_features()` (`gradient.rs:2542`), `fit_fill()` (`gradient.rs:1936`)
**Pipeline position:** `merge_bands` (`lib.rs:373`) runs after blend absorption (stage 04) and before `carve` (`lib.rs:396`); `carve` runs before `split` (`lib.rs:409`, stage 04's face-splitting). Per-face fill selection (`fit_fill`/`fit_candidates`) is the same machinery, called later by `inkvec-cli` once faces exist.

## What problem this solves

`color::label_image` hands every pixel the nearest of a small, discrete set of palette colours. A flat-coloured icon renders correctly under that scheme. A smooth gradient does not: it has no flat regions to find, so the palette quantises it into bands, one per palette entry the ramp crosses. Left alone, each band becomes its own face with its own flat fill. The module doc comment gives the concrete cost: a `gradient_linear` test case came back as four flat layers costing 58 parameters, where the ground truth is one gradient with 12 (`gradient.rs:1-9`).

Model selection is not limited to "flat or gradient" — a region's fill is chosen from flat (3 parameters), linear (10) and radial (9, or 11 elliptical), by the same minimum-description-length objective used throughout the tracer:

```
cost = 0.5 * chi2 + lambda * params
```

`chi2` is summed squared residual in sRGB, scaled by the measured per-pixel noise `sigma_noise`; `params` counts the numbers that would actually be written into the SVG; `lambda` weights the trade. See Constants below for the two different `lambda`s in play across the tracer.

Two further problems this module solves, beyond band merging and model selection:

- **A feature painted on top of a gradient** — a seam, a dot, a stroke end the palette quantised into its surroundings — leaves the fill fitter looking at a region with a cluster of pixels no single fill model can explain, and its only tool is to spend a gradient explaining it (`carve_residual_features`, below).
- **The gradient fitting cost dominates the tracer's runtime.** With every optional stage disabled a slow emoji still took 10.9 s; capping the palette (which is what feeds the per-region gradient search) brought it to 6.3 s (`ColorOptions::gradients` doc comment, `lib.rs:174-178`, quoted in full below). `--no-gradients` exists as a genuine fast path for exactly this reason.

## Inputs and outputs

- `merge_gradient_bands_with_ink(labels: &mut [u16], rgb: &[[f32;3]], w, h, pal: &Palette, sigma_noise: f64, lambda: f64, deadline: Option<Instant>) -> (Vec<FillFit>, Vec<usize>)` — mutates `labels` in place (bands that merge get a fresh label past the palette's own range) and returns one `FillFit` per resulting label id, plus a parallel `Vec<usize>` mapping each label back to the palette entry it was cut from (a merged gradient maps to its first band's entry).
- `carve_residual_features(labels: &mut [u16], rgb, w, h, pal, fills: &mut Vec<FillFit>, ink: &mut Vec<usize>, sigma_noise, lambda, min_size) -> usize` — further mutates `labels`, appends newly minted flat regions to `fills`/`ink` in place, and returns the count minted.
- `fit_fill(rgb, w, h, labels, label, sigma_noise, lambda) -> FillFit` — the single-region entry point used once faces (not just palette-merged bands) exist; `select(fit_candidates(...))`.
- `FillModel` (`gradient.rs:99`) — the fitted geometry: `Flat([f32;3])`, `Linear { p0, p1, c0, c1, interp, mids }`, `Radial { c, r, c0, c1, interp, aspect, angle, mids }`. Points are pixel-centre coordinates, matching the tracer's `-0.5 -0.5 w h` viewBox (`gradient.rs:104`).
- `FillFit` (`gradient.rs:282`) — `{ model: FillModel, chi2: f64, params: f64, cost: f64 }`, the fitted model plus the numbers the selection was made on.
- `Interp` (`gradient.rs:90`) — `LinearRgb` or `Srgb`, which space the gradient interpolates its stops in; a model parameter, not a rendering convention (see below).

## How it works

### Four design decisions stated up front in the module doc (`gradient.rs:11-39`)

1. **Fit in linear light, and also in sRGB.** Physically composited and rendered gradients are linear in linear RGB; SVG itself interpolates stops in sRGB by default, and so does every renderer that produced the training corpus, so a gradient authored in SVG is linear in sRGB and gamma-curved in linear light. Both spaces are fitted (`INTERPS = [LinearRgb, Srgb]`, `gradient.rs:95`) and MDL picks whichever explains the pixels; the winning space is part of the model and is emitted with it (`color-interpolation="linearRGB"` when needed, `gradient.rs:1963`, `interp_attr`).
2. **The residual is measured in sRGB, with 8-bit quantisation as part of the observation model.** An 8-bit value `v` means the true value lies in `[v - ½LSB, v + ½LSB]`; a prediction inside that interval is fully consistent with the observation. The residual therefore has a **dead zone of half an LSB** (`QUANT_HALF_STEP = 0.5/255.0`, `gradient.rs:82`) and is Gaussian in `sigma_noise` beyond it. Without this, a plain Gaussian at the noise floor treats sub-LSB rounding as signal, and "two gradients with fourteen parameters explain the rounding better than one gradient with seven" — precisely the banding this module exists to remove (`gradient.rs:20-31`).
3. **Only strictly interior pixels enter a fit** — every 4-neighbour in the region, and not on the picture edge. Anti-aliased edge pixels are blends with the neighbouring region: evidence about geometry, not about the fill.
4. **Be conservative.** `cost = 0.5*chi2 + lambda*params`; on a noisy flat region a gradient can only lower chi2 by a few units, which `lambda * 7` (the linear-over-flat parameter gap) outweighs, and a gradient must also produce visible contrast, or it is fitting noise regardless of what chi2 says.

### `merge_gradient_bands_with_ink` (`gradient.rs:2138`, 371 lines)

1. **Connected components.** 4-connected flood fill of the current `labels` (`gradient.rs:2153-2190`), recording, for every pair of touching components, the length of their shared boundary (`adj`, a `HashMap<u32,u32>` per component, `gradient.rs:2194-2210`). Components rather than raw labels, because a band's palette colour can also belong to an unrelated flat region elsewhere in the image, which must not be dragged into the merge.
2. **Evidence mask.** `fill_evidence()` (see below) is computed once, over the palette inks of the labels as they stand before any band merges (`gradient.rs:2214-2217`).
3. **Per-component fits.** Every component is fitted independently and in parallel with `rayon`, since none depends on another (`gradient.rs:2256-2262`), via `fit_group`, which caps any single fit at `FIT_PIXELS_CAP = 65536` pixels taken by uniform stride and scales `chi2` back up by the subsampling factor so costs stay comparable across region sizes (`gradient.rs:2227-2251`; measured bit-identical in output to fitting every pixel at 1024 and 2048 px on the two profiling logos referenced in the comment).
4. **Greedy agglomeration.** Each round:
   - Gather every adjacent pair whose shared boundary is at least `MIN_SHARED_BOUNDARY = 3` pixels and where at least one side is already a gradient — **two individually flat regions are never unioned just because a ramp happens to interpolate between them**; bands only exist because a smooth ramp was quantised, and a quantised band still carries the ramp inside it, so this check runs *before* the union is fitted (it is otherwise the single largest cost in the tracer, `gradient.rs:2301-2311`).
   - Fit every such pair not already cached, in parallel (`gradient.rs:2318-2336`).
   - Pick the pair with the largest cost saving `gain = cost(a) + cost(b) - cost(union)`, provided `gain > 0` and the union is itself a gradient; merge it, re-route adjacency, invalidate (but do not discard) cached union fits touching the merged component (`gradient.rs:2338-2432`).
   - **Stale-cache handling** is a deliberate performance decision: a cached union fit becomes stale once one of its members absorbs something else, but it is refitted only when it would win the round, not eagerly. A large gradient region swallowing fifty two-pixel flecks along its edge used to invalidate its union fit with every other neighbour on every absorption — 2,500 refits of a 13k-pixel region, 19 s of a 23 s trace on one logo (`gradient.rs:2274-2278`). Stale *flat* unions are dropped outright rather than kept (two Noto icons moved 0.005 dE00 when they were kept — a region that came out flat before growing can come out a gradient after, `gradient.rs:2415-2421`); stale *gradient* unions are kept and only refitted before being accepted, because the stale cost under-estimates the true union cost (fewer pixels than the eventual union), so the stale gain over-estimates it and any stale winner is caught and refit before acceptance — scoring it the other way (against the cached model) was tried and *over*-estimated the cost, stopping a radial gradient's own bands from ever merging (`gradient_radial` synthetic case: 0.04 -> 0.23 dE00, 18x the parameters, `gradient.rs:2422-2427`).
   - Runs until no pair saves cost, or the optional `deadline` passes — the deadline exit is graceful: every merge already accepted stands, so the output is a correct trace with more fills than optimal rather than a wrong one (`gradient.rs:2280-2291`).
5. **Write-back.** A thin flat component (no interior pixels of its own) keeps its palette label and is pooled with every other flat component of that entry for a joint refit — a thin component has no reliable colour estimate of its own, and pooling the wide interiors with it is what supplies one; a flat component *with* an interior of at least `MIN_GRADIENT_PIXELS = 16` interior pixels keeps its own colour rather than being pooled, because two disconnected regions that happened to quantise to the same palette entry are two objects (a lizard's belly plateau came out 17 LSB too dark sharing a palette entry with the darker end of a nearby ramp, `gradient.rs:2463-2470`). Every gradient (merged or not) gets a fresh label `pal.len() + i`.

### `carve_residual_features` (`gradient.rs:2542`, 230 lines)

Runs after band merging, before faces are split into connected components. The palette sees colours, not features: a two-pixel white seam through a black shape, a pair of dots, the end of a thin stroke all quantise to the ink around them. The fill fitter then sees a solid region with a residual cluster it cannot explain and buys a gradient to cover it — three radials on solid black (`ebox`), black lightening to grey at a rim (`luanti`), a dark core on a flat face (`kiss`, `zebra`) — see `crates/inkvec-trace/src/gradient.rs:2524-2530`.

1. Compute `fill_evidence` fresh (over the *current* fills, `pure0`) and, per label, the **flat colour** — the per-channel median of pure interior pixels — but only where there are at least 8 such pixels (`med_samples`, `gradient.rs:2595-2620`); this is a gate, not the residual test.
2. **The residual test is against the fill the fitter actually chose, not the region's flat colour** — this was the reverse of the original design. Testing against the flat colour was tried and rejected: it carved hard-edged shading the fitter had legitimately captured with a gradient (`noto 1f9d1_1f3fc_200d_1f37c` +0.13 dE00, `1F3DD` +0.10). Requiring both residuals to fail simultaneously was also tried, and stricter still. On a 51-icon dev set the flat rule with guards looked better (`0.7797` vs `0.7888`), but the full 980-icon set **reversed** that ranking: against the plain fit-residual rule with no extra guards, flat+guards was 82 icons better / 193 worse in dE00 (net +0.0022, i.e. worse) and fit+guards 57/191 (net +0.0031), both at an unchanged objective. The plain rule ships (`gradient.rs:2621-2634`).
3. A pixel is a candidate when `|colour - fill.color_at(x,y)|` (max over channels) exceeds `thr = max(8*sigma_noise, CARVE_RESIDUAL)` — see Constants — **and** it is interior and passes `fill_evidence` (not a blend). Blend exclusion matters concretely: a two-pixel grey fleck where two black strokes almost touch is anti-aliasing of the *gap*, not a thing to draw; minted as its own region it paints over the gap (`send_and_archive`: two such flecks cost 0.19 dE00, `gradient.rs:2571-2575`).
4. 4-connected components of the candidate mask, within one label, of at least `min_size.max(4)` pixels, capped at `CARVE_MAX = 64` regions per image (a guard against a textured region shattering into hundreds of tiny carved pieces — the earlier idea of capping a cluster's size relative to its parent (a fifth of the parent, or 200 px) was tried and rejected: with the (also-rejected) step-edge test it lost more genuine small features than it prevented explosions, `gradient.rs:2685-2701`).
5. Each surviving cluster is minted as its own flat region (median colour), named by nearest palette entry, and every parent that lost pixels is refit without them (`gradient.rs:2703-2769`).

A **step-edge test** (requiring the mean contrast across a cluster's boundary with the rest of its parent to itself clear the residual threshold) was tried alongside the flat-colour rule and rejected along with it: sound reasoning against a flat residual (a genuine gradient's bright end is also a small, high-residual cluster, but reached by a ramp where a seam is a step) but it only ever ran alongside the flat rule that does not ship, and cost a four-neighbour sweep of every candidate cluster for nothing on the default path (`gradient.rs:2694-2701`).

### Fill fitting

**`fit_flat` (`gradient.rs:644`).** The flat model is the **per-channel median** of the (possibly strided, capped at `fit_cap()` samples) interior evidence pixels, not the mean. This is a robust-statistics decision stated directly in the doc comment: the flat model is scored by the same sRGB residual as every other candidate, so it has to be the colour that *minimises that residual* — and for a dark region with a few light outliers (blend pixels the evidence test let through, a lost dot), the linear-light mean lands at a grey no pixel actually has; every pure pixel then pays for the outliers, and a gradient that places the true colour in the middle and the outliers at its rim wins by comparison. Measured concretely: on `luanti`, a solid black region whose interior is genuinely 0.00 fitted flat at 0.16 under the mean. The per-channel median is the residual's own robust optimum, and equals the mean on a clean region anyway (`gradient.rs:635-643`).

**`fill_evidence` (`gradient.rs:1815`).** Decides which pixels are allowed to vote on a region's *fill*, as distinct from its *label*: after blend absorption, every anti-aliased pixel already carries the label of the ink it is mostly made of, so the label map alone cannot say which pixels are pure. A pixel is a blend (excluded) when its colour lies, within noise tolerance, on the segment from its own ink to the ink of another label found within **two pixels** of it (`x0..=x1`/`y0..=y1` windows of radius 2, `gradient.rs:1842-1843` — one pixel was tried and measured worse: `twemoji flag` +0.07, `emoji_u1f923` +0.04, and did not recover the thin-hair case it was meant for). Concretely, without this exclusion a wedge tip that is nothing but blend pixels buys a radial gradient on an otherwise solid black shape (`luanti`: black lightening to `#6d6d6d` over the last tenth of a slab; `ebox`: three gradients on solid black, `gradient.rs:1806-1814`). Pixels within the noise of their own ink, or off every such segment, remain evidence — a genuine gradient's colours are not on a line towards a *neighbour's* ink, so its samples are unaffected.

**`fit_fill` / `select` (`gradient.rs:1936` / `1728`).** `fit_candidates` builds every admissible candidate: the flat fit always first, then (if the region has `>= MIN_GRADIENT_PIXELS = 16` samples and the flat cost does not already beat the cheapest gradient could possibly cost — `lambda * PARAMS_RADIAL`, an exact short-circuit since no gradient's cost can fall below its own parameter floor, `gradient.rs:1615-1628`) linear, radial and elliptical-radial candidates in both interpolation spaces, each gated by:
- `contrast >= max(3*sigma, MIN_VISIBLE_CONTRAST) * scale` (`INKVEC_MIN_CONTRAST` scales this; see Environment overrides and Open questions)
- `support >= MIN_RAMP_SUPPORT = 0.10` — the candidate must visibly shade at least a tenth of its samples, or it is explaining a feature (a lost dot, a chamfered tip), not a genuine gradient.

Then a **ramp-vs-step decision** (`gradient.rs:1691-1723`): a gradient is the right model for shading and the wrong one for two inks the palette merged into one, and *both* raise a flat colour's residual, so comparing a gradient candidate against the flat fit's own residual cannot separate them — an earlier version of this test that did compare against the flat residual declined gradients everywhere and cost the corpus a fifth of its quality. What separates a genuine ramp from a step wearing a ramp's clothes is how the *alternatives* rank: measured over the regions the tracer paints flat where the artwork actually varies (`bench/research/decoding/h12_gradient_gap.py`), the best linear ramp removes 13% of the error there and the best pair of flat colours removes 66% — those are steps. So the step is priced directly: `chi2_two_flats` (the best bimodal two-colour split) is compared against the best gradient candidate's `chi2`, and if `chi2_two_flats < BIMODAL_MARGIN * best_grad_chi2` (`BIMODAL_MARGIN = 0.85`, overridable with `INKVEC_BIMODAL`), every gradient candidate is discarded and the region stays flat.

Finally `select` (`gradient.rs:1728`) takes the candidate of lowest `cost`, ties going to the earlier (simpler) candidate — flat is always first in the list, so a tie always resolves to flat.

### `bic_lambda` vs the fitter's `lambda`

`bic_lambda(n) = 0.5 * ln(n)` (`gradient.rs:297`) is the value of `lambda` at which the MDL cost equals the Bayesian information criterion for `n` observations: it grows slowly with region size, so a large region must earn a gradient with proportionally more evidence than a small one needs (`gradient.rs:292-296`). It is a function of **pixel count** and is used throughout `lib.rs` wherever a fill decision is made (`gradient::bic_lambda(img.width * img.height)`, e.g. `lib.rs:306,367,389,484`).

This is a **different quantity** from `inkvec-fit::FitConfig::lambda`, which is derived from `crates/inkvec-fit/src/lib.rs:74-80`:

```
lambda = ln(extent / precision)
```

— the number of nats it costs to write down one coordinate confined to `extent` at output resolution `precision` (a 256px canvas at 0.1px precision: `ln(2560) ≈ 7.85`). One is a per-*fill* description-length weight tied to sample count; the other is a per-*coordinate* weight tied to canvas size and output precision. Both instantiate the same `cost = 0.5*chi2 + lambda*params` objective, at two different points in the pipeline (fill selection here, curve segmentation in `inkvec-fit`), with two independently derived `lambda`s.

### `FillModel` / `FillFit` / `color_at`

- `FillModel::params()` (`gradient.rs:168`) returns the parameter count used in the cost: `PARAMS_FLAT = 3.0`, `PARAMS_LINEAR = 10.0` (+`PARAMS_STOP = 4.0` per interior stop), `PARAMS_RADIAL = 9.0` or `PARAMS_RADIAL_ELLIPTIC = 11.0` (+ stops).
- `FillModel::color_at(x, y)` (`gradient.rs:197`) evaluates the model's predicted sRGB colour at a pixel-centre position — `Flat` returns its one colour; `Linear`/`Radial` compute the normalised axial or radial coordinate `t` (`linear_t`/`radial_t`, clamped to `[0,1]` — the model pads flat beyond its defined extent) and evaluate `eval_stops` across `c0`, any `mids`, `c1` in the fitted `Interp` space.
- `FillModel::representative()` (`gradient.rs:224`) returns one stand-in colour — the flat colour, or the midpoint of a gradient's two end stops — used wherever a region only needs to be told apart from a neighbour (boundary unmixing), not rendered.
- Elliptical radial gradients matter empirically: Illustrator writes nearly every radial gradient with a `gradientTransform`, and in the Noto corpus 217 of 279 radial gradients are elliptical with aspect above 1.1; fitting a plain circle to any of those is wrong in a way no colour tolerance hides, and the resulting unmerged bands are the visible symptom (`gradient.rs:118-122`).

### The `--no-gradients` fast path

Quoted in full, from `ColorOptions::gradients`'s doc comment (`crates/inkvec-trace/src/lib.rs:171-179`):

> Turning this off is a genuine fast path, not a cosmetic one. Gradient fitting is the dominant cost in the tracer: with every optional stage disabled a slow emoji still took 10.9s, and capping the palette — which is what feeds the per-region gradient search — took it to 6.3s. The CLI's `--no-gradients` used to replace the fitted model with a flat one *after* paying for the fit, so it changed the output and saved nothing.

Concretely: when `opts.gradients` is `false`, `merge_gradient_bands_with_ink` is never called at all (`(Vec::new(), Vec::new())` is substituted, `lib.rs:359-372`) and `carve_residual_features` is skipped too (`lib.rs:379`) — the search itself is what is expensive (the radial-centre search alone is up to 600 residual evaluations per candidate, `gradient.rs:2080-2084`), not merely the choice of which model to keep. The CLI help text repeats the same framing: `--no-gradients Skip gradient fitting entirely and fill flat. A genuine fast path: gradient fitting dominates runtime` (`crates/inkvec-cli/src/args.rs:165-166`).

| `CENTRE_SEARCH_SAMPLES` | 1024 | samples the radial-centre hill-climb evaluates on | measured: "1024 gives the same output as 4096 on every logo measured and is four times cheaper... this search was most of a union fit's cost in the band merge" (`gradient.rs:2080-2084`) |

See Open questions. |

## Failure modes and edge cases

- **`luanti`** appears twice as a regression witness: (a) a solid black region's flat fit under a linear-mean average lands at 0.16 rather than the true 0.00, motivating the median (`gradient.rs:635-643`); (b) black lightening to `#6d6d6d`/`#6a6a6a` over the last tenth of a slab/elliptical radius is a carved feature or a support-gated refusal, not shading (`gradient.rs:73-78`, `1806-1814`).
- **`ebox`**: three radial gradients fitted to what is actually solid black with seams — the running example for why `carve_residual_features` exists at all, and why the flat-colour residual test (which would have carved the seams and left the fit residual test to still buy gradients) was rejected in favour of testing against the chosen fill.
- **`send_and_archive`**: two anti-aliasing flecks between near-touching black strokes cost 0.19 dE00 when carved as if they were features — the reason `carve_residual_features` excludes blend pixels via `fill_evidence`.
- **`gradient_radial` (synthetic)**: scoring a stale cached union against its own cached model rather than refitting overestimated the union's cost and stopped a radial gradient's bands from merging at all — 0.04 -> 0.23 dE00, 18x the parameters. This is why stale gradient unions are refit before being accepted rather than scored as-is.
- **h-series / noto-emoji family**: 98 of 100 icons carrying this family's characteristic error fail the visible-contrast floor by a hair (contrast 0.0039-0.0055 against a 0.0059 floor) while the MDL cost itself would have accepted the gradient by a wide margin — the reason `INKVEC_MIN_CONTRAST` exists as an override to reprice the floor across the whole set (`gradient.rs:1630-1638`).
- **Dev-set vs full-set reversal** (carve's flat-vs-fit residual choice): a decision that looked better on a 51-icon dev set (`0.7797` vs `0.7888`) reversed on the full 980-icon set. This is stated explicitly as the reason the plain fit-residual rule ships instead — a recorded caution about trusting small held-out sets.

## Open questions

- `MAX_SLIVER_MISFIT` (`gradient/stops.rs:15`) gates stop acceptance inside `fit_mid_stops` (`gradient/stops.rs:137`), the multi-stop interior-knot fitter that every linear/radial/elliptical gradient candidate is run through. `fit_mid_stops` fits a robust piecewise-linear colour profile via `fit_piecewise` (`gradient/stops.rs:62`), reweighted over `IRLS_ROUNDS = 2` rounds (`gradient/stops.rs:11`), and searches for the best position of each new interior stop by golden-section search. Once a candidate stop position `k` is chosen, the fitted samples are split into the side before `k` and the side at-or-after `k` (`gradient/stops.rs:263`); if the smaller side holds fewer than a tenth of the samples (a "sliver") and that side's median residual exceeds `MAX_SLIVER_MISFIT` (4.0) times the larger side's median residual (floored at `1/255` to avoid blow-up near zero), the candidate stop is discarded and no further stops are tried for that fit (`gradient/stops.rs:273-278`). In effect, this stops the fitter from adding an interior colour stop to explain a small cluster of badly-fit pixels — such as a stroke absorbed into a gradient region — rather than genuine multi-stop shading. It is reachable from both `merge_gradient_bands_with_ink` and `fit_fill`: both route through the shared `fit_pixels` (`gradient.rs:1496`), which calls `fit_samples` (`gradient.rs:1338`), which calls `fit_mid_stops` (`gradient.rs:1425`); `merge_gradient_bands_with_ink`'s own `fit_group` closure calls `fit_pixels` directly (`gradient/bands.rs:225`). **Unverified:** the source gives no stated derivation for why the threshold is 4.0 specifically, as opposed to any other multiplier.
- Several thresholds — `MIN_GRADIENT_PIXELS = 16`, `MIN_VISIBLE_CONTRAST = 1.5/255`, `MIN_RAMP_SUPPORT = 0.10`, `MIN_SHARED_BOUNDARY = 3`, `CARVE_MAX = 64` — are stated qualitatively ("below this it is invisible", "a guard against shattering") but have no reported sweep or measured alternative in the source comments, unlike `BIMODAL_MARGIN`, `CENTRE_SEARCH_SAMPLES`, or the min_region history in stage 04. These read as chosen rather than measured.
- The absorption thinness/dominance percentages quoted in stage 04 and the gradient-evidence radius here (two pixels, not one) are both explicitly measured against alternatives; by contrast `CARVE_RESIDUAL`'s "8 times the noise" multiplier has no comparison point recorded — only the floor (0.06) is justified by a worked example.
- `fit_flat`'s stride-based subsampling (`stride = (n / fit_cap()).max(1)`, `gradient.rs:649`) takes every `stride`-th pixel rather than a random or blue-noise subsample; whether this systematically biases the median on a region with any positional structure (e.g. a gradient-like drift within a nominally flat region) is not discussed in the source.
